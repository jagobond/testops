# TESTOPS-87 - The page is right and the memory is wrong

## Why this exists

TESTOPS-85 was accepted, and two things carried forward from its review, both about honesty that stops at the page.

1. **The stored `quoted_copy` reason is inverted for the compound case** (`level_fitness.py:1412`). For
   `a "Welcome" message is created` it stores that `message` "is text a person is shown inside the assertion's display copy
   'Welcome'" - which is backwards: `Welcome` is what is shown, `message` is the head noun. The rendered sentence is right,
   so a reader never sees it, but the store is the product's memory: every later rebuild, export or query reads the wrong
   fact.
2. **AC3's empty-reason pin is a hand-written list**, and the build report claims more than the test delivers ("a new state
   cannot appear without a sentence"). A seventh near-miss kind born with an empty reason passes the suite.

## Acceptance criteria

| id | criterion |
|----|-----------|
| AC1 | The stored reason names the **right** part of the sentence: the caption as the shown text, the head noun as the head. Pinned by asserting the stored string for the compound fixture, not only the rendered page sentence. |
| AC2 | The empty-reason check is a **sweep over what the fixture suite produces**: it enumerates every near-miss state generated by the fixtures at run time and asserts each carries a non-empty, actionable sentence. Adding a seventh kind tomorrow must fail the test until it has a sentence. Proving it: add a temporary state with no sentence in a scratch run and show the test fails. |
| AC3 | The build report may not claim more than the test does: if the sweep is partial, the report says which states it covers and which it does not. |
| AC4 | No weakening: corpus 43 claims / 1 repeat / 12 near misses / 0 moves; suites green; contracts green; goldens unchanged or listed. |
